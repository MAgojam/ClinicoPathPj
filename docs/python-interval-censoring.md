# Numeric interval-censoring input preparation — 0.3.50

**Survival Py → Data preparation → Interval-censoring inputs** is a standalone
`pyintervalcensoring` utility. It prepares numeric inputs and does not fit a survival
model or recode another analysis's outcome. It is an extra utility, not a completed
baseline port. All calculations run in bundled NumPy; no additional user packages
or network access are required.

| Prepared endpoints | Classification / audit code |
|---|---|
| Finite left = right | Exact / 1 |
| Finite left < right | Interval-censored / 3 |
| Open left, finite right | Left-censored / 2 |
| Finite left, open right | Right-censored / 0 |
| Both open/missing | Uninformative; saved pair/type missing |
| Original left > right | Invalid; saved pair/type missing |

The reference is `survival::Surv(left, right, type="interval2")`. Bound order is
checked **before** nonfinite values become open bounds, including infinities. This
order matters, for example +Inf left with a finite right is invalid. Nonfinite
bounds follow the reference; inspect the original representation in the preview.

Only scalar numeric inputs are accepted. Factors/text/date classes require explicit
conversion; factor indices must not masquerade as time values. Both columns must
share units and origin. Signed finite values are retained because the numeric scale
is not assumed to be elapsed duration; the utility cannot verify whether negative
values are appropriate for the intended application.

The canonical saved pair clears both bounds for reversed/uninformative records.
A single missing prepared endpoint can instead be a valid open bound. **Do not apply
ordinary complete-case deletion to the pair.** Save both endpoints together. In R,
`Surv(left, right, type="interval2")` takes no third event argument. The saved nominal
classification is an audit label, not an event indicator for that constructor.

Native tables distinguish informative, reversed and uninformative records, count
infinity/negative source rows and show censoring-type percentages among informative
records only. No informative rows means unavailable percentages. The bounded preview
shows original bounds, canonical bounds, source identities and classification. All
supplied rows remain aligned in saved outputs, including valid one-sided records.

The typed **Interval Censoring Input Examples** dataset has ten synthetic pairs:
three exact, two left-censored, one right-censored and two interval-censored records,
plus one reversed and one uninformative pair. Endpoints are continuous numeric
variables; no type editing is needed. No patient data or model estimates are included.

The CSV and typed OMV example are generated by scripts under `data-raw/`. The OMV is
written with the already-installed developer tool `jmvReadWrite`; that package is
not a runtime dependency for module users.

The shared bridge still rejects infinite source values by default. This utility
opts in only its two numeric Variable roles through literal
`allowInfinite: [left, right]`. The generator rejects unknown/non-numeric/duplicate
roles. Strict JSON uses signed `Infinity` string tokens within explicitly numeric
columns; Python decodes them to floats before interval checks. Other analyses
retain the existing rejection policy. Native tests cover both paths.
