# Linked IHC views — 0.3.12

Implemented 2026-10-26 as an extension of `pyihcheatmap`, within the existing
Orange-inspired exploratory workstream. This adds no baseline target or new analysis.
Julia is retained separately as a deferred backend idea in the migration plan.

## Implemented behavior

- Optional linked heatmap/scatterplot, disabled by default to preserve existing analyses.
- Native X/Y marker roles, restricted to two distinct selected heatmap markers. Blank roles
  use the original first/second marker selection, independent of clustering leaf order.
- Native complete-pair cohort and original-source-row tables, plus a static Image scatterplot.
- Pairwise-complete plotted rows, with explicit omitted-pair counts relative to the retained
  heatmap cohort. All-marker-missing/complete-row exclusions retain their existing definition.
- Raw/z-score display values and original source identity remain aligned after clustering.
  Repeated patient IDs never merge rows. There is no imputation or fitted association model.
- Cell/point focus or activation links row highlights. Point keyboard activation supports
  Enter/Space; clear resets selection. Search highlights without removing observations.
- Local X/Y dropdowns recompute display coordinates/counts only. They do not call a backend,
  change saved options, subset inference, or change native tables/static plots. Save a pair
  by changing the native X/Y roles. Local pair choices/highlights are transient.
- Empty pairs leave the heatmap available with an explicit warning and empty native scatter.

## Checks

Python fixtures verify transformations, finite-pair extraction, repeated IDs, missingness,
clustering alignment, invalid pairs, unchanged default heatmap output, empty scatter behavior,
and hostile annotation escaping. Native R checks compare displayed pair coordinates with
independent base-R `scale()`, verify source rows and omission counts, render serialized
plot state without the analysis dataset, and exercise enabled → disabled → incomplete →
valid recovery against a fresh analysis.

The offline jsdom harness checks linked cell/point focus, Enter activation, local marker
switching, omitted pairs, clear/search behavior, literal hostile annotations, and distinct-marker
handling. Native option dispatch and fetch are configured to fail if called by inspection.
This is a DOM test, not a real-browser or jamovi GUI test.

Compiler preparation initially rejected `enable` on TargetLayoutBox. Moving that binding
to the VariablesListBox controls resolved the schema placement; compilation is checked
separately from generator validation.

## Native desktop follow-up — 0.3.12 / 0.3.13

On macOS arm64 / jamovi 28.13, the standard 0.3.12 package was installed via the module
Sideload interface. A fresh engine loaded the synthetic IHC document. Enabling the linked
scatter produced Ki67/ER with 11 heatmap rows, 9 complete pairs and 2 omitted pairs. Clicking
the second scatter point highlighted only source row 2 (S01 / Edge); clicking source row 1's
heatmap cell switched the linked selection to S01 / Center. Repeated specimen IDs stayed
distinct. Switching local Y to PR showed 10 complete pairs / 1 omitted, while the native
Ki67/ER table remained 9 / 2. Native Image → Export → PNG succeeded and was decoded/inspected.

A separate saved 0.3.12 validation document reopened in a fresh engine with the native
9-pair output and both images. The local PR view/highlight reset to the saved default pair,
as intended; the transient state was not persisted as native options.

Desktop inspection exposed a supplier problem: with `persistentItems: false`, the original
heatmap/annotation assignments emptied the available-variable list, obstructing reuse of
selected markers for native scatter roles. Version 0.3.13 changes only the IHC supplier to
`persistentItems: true` (plus version metadata). After GUI installation and a fresh engine,
all six source variables remained available. Dragging Ki67 into X and PR into Y preserved
the three heatmap markers and recalculated native results to 10 complete pairs / 1 missing.
The custom pair was saved, closed and reopened in another fresh engine. Both native roles,
10-pair table, native scatter and heatmap restored; the restored scatter exported to PNG.
